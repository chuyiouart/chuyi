失败版本留下，下一次才知道改哪里

模型、打印小样、涂装测试或网页更新失败后，很多人第一反应是删掉重来。文件夹看起来干净了，但几天后同一个问题再出现，已经找不到当时是哪一版、哪里出错、用过什么条件。 今天要解决的是怎样留下失败版本，又不让它和当前采用版混在一起。保留的目的不是收藏错误，而是让下一次修改能回到真实对象，比较前后变化，并知道哪些结论仍未确认。

核心判断

失败版本有用的前提，是身份和现象能对应。至少要知道它来自哪个对象和文件、当时要验证什么、实际看到了什么，以及哪些原因还只是猜测。只有一张失败截图或一个叫‘旧版’的文件，通常不够。

保留不等于继续使用。失败版进入只读归档，修改版另存并单独检查；真正采用前，要在相同或可比较的条件下复查原问题。AI可以协助归组和比较记录，不能替人确认实物、结构或线上结果。

步骤或标准

把失败版本当成一次可复查的观察记录，和当前采用版分开放，再围绕一个具体问题做下一次测试。

  • 给失败版本保留独立文件或实物样，记录日期、对象、版本来源和当时想解决的问题；不要用新的同名文件覆盖它。
  • 只写已经看到的现象，例如哪一处气泡、接缝错位、文件打不开或页面断链；原因没有检查前标为待查，不先下结论。
  • 把失败版本与它对应的输入、参数、照片、切片、测试条件或公开读回放在同一关系里；找不到对应项时如实记录缺口。
  • 另存后续修改版，并写清只改了什么。比较时保持同一观察条件，避免把光线、角度或文件格式变化误当成问题已经解决。
  • 用一个小范围动作复查，例如重新导出一个文件、做一个局部样或在相同角度检查表面；通过和未通过都保留结果。
  • 确认新版本解决原问题且没有带来新的关键问题后，再决定采用；旧失败版本进入只读归档，不继续拿来制造或公开发布。

常见错误

失败记录失去价值，往往不是少保存一个文件，而是版本身份、可见现象和后续采用关系没有分开。

  • 为了让目录整齐，直接删掉失败文件和样件。后果是问题再次出现时没有原对象可比，原因和修正效果都难以复查。
  • 用同一个‘最终版’文件名反复覆盖。后果是前后版本身份消失，无法证明改了哪一处，也可能把错误文件带进下一步。
  • 只留一句‘失败了’，不写可见现象和条件。后果是下次只能重新猜，AI也容易把缺失信息补成看似完整的原因。
  • 看到新版本外观更顺，就宣布问题解决。后果是光线、角度或渲染差异可能遮住原问题，实物与结构并未真正通过。
  • 把所有失败样都继续当成可用生产文件。后果是只读证据与当前采用版混在一起，制造、网页和交接时容易选错。

与短期课程的关系

失败版本可以出现在五个制作阶段：方向草案、AI辅助模型、打印和实测、涂装包装、网站发布。课程内部会记录阶段和检查点，对外可以理解为：先保留当时对象和现象，再修改一个明确问题，最后按原条件复查。

3天聚焦路线适合围绕一个失败点完成版本整理、一次有限修改和一次真实复查；4–5天可在通过后连接相邻阶段。版本身份、原问题和复查依据没有对上时，不把新文件当成已通过，也不进入下一步制造或公开发布。
