具体问题

作品页在电脑上排得整齐，到了手机上可能完全是另一回事。主图会被裁掉角色的头或脚，细节图缩得看不清，按钮挤在一起，模型查看区还可能和页面滚动抢手势。只在电脑上拖窄浏览器窗口，不能代替真实手机检查。

今天要解决的是：怎样拿真实手机把图片、页面布局、链接和三维模型逐项看一遍，并把问题记录到能复现的程度。目标不是证明页面‘大概能开’，而是确认读者能看清作品、完成操作，也知道哪里仍要修改。

核心判断

手机检查要同时看显示和操作。显示包括主图主体是否完整、图片是否清楚、段落是否容易读、横向内容有没有撑出屏幕；操作包括链接能否点开、模型能否旋转缩放、单手是否容易点到入口，以及拖模型时页面会不会跟着乱跑。

一次设备通过也不等于全部通过。至少要记录真实设备、屏幕方向、访问页面、网络条件和复现动作；关键问题修改后，再回到同一台手机重查。AI或自动工具可以帮忙列清单、查代码和整理报错，但不能替代手指操作、实际图片读回和真实设备上的模型加载。

步骤或标准

按读者真正打开页面的顺序检查，问题更容易定位。

  • 锁定要检查的页面版本，准备真实公开或预览地址、当前主图与画廊、展示模型和行动入口；不要把不同版本的图片、代码和模型混在一次检查里。
  • 先用一台真实手机竖屏打开页面，从顶部读到结尾，检查首屏主体、图片比例、段落宽度、横向溢出、留白、按钮间距和页面是否出现明显跳动。
  • 逐张打开主图与细节图，确认角色头脚、关键材料和接口没有被裁掉，清晰度足够；再转为横屏复查，不用放大截图掩盖问题。
  • 进入三维查看区，实际尝试加载、旋转、缩放和返回页面；观察手势是否与页面滚动冲突，模型、材质或相机是否异常，失败时有没有可理解的替代内容。
  • 点开页面内真实链接和报名入口，检查是否进入预期地址、返回是否顺畅、可点击区域是否适合拇指；不提交表单，不触碰后台或个人数据。
  • 记录设备、方向、页面位置、复现动作、实际现象和截图或屏幕录制依据。修正后在同一条件重查，再补一台不同尺寸设备做有限复核。

常见错误

移动端问题经常不是代码完全失效，而是检查条件太轻。

  • 只在电脑浏览器里把窗口拖窄。后果是真实手机的触控、地址栏、像素密度、性能和方向变化都没有被检查。
  • 看到首页能出现就宣布完成。后果是画廊后半段、报名链接、模型交互和页面底部的溢出问题继续留在公开页面。
  • 只看图片有没有加载，不看主体有没有被裁。后果是文件虽然显示成功，角色头脚、材料细节或尺度证据却不完整。
  • 拖动模型时页面跟着滚，也当作可以使用。后果是读者很难稳定旋转或缩放模型，甚至无法返回正常阅读。
  • 修改后换一台设备随手看一眼。后果是原问题没有按相同条件复现，无法确认修复是否真的有效。

与短期课程的关系

这项练习属于阶段5的独立站、三维展示与发布验收，也会回查阶段4准备的作品图片和说明。做完后要能拿出移动端检查清单、真实设备上的问题记录、修改前后依据，以及仍未确认的设备或网络条件。

3天聚焦路线可以围绕一个现有作品页完成主图、画廊、一个模型区和主要链接的手机检查；4–5天可继续修改页面、补图片派生版本、复查更多尺寸并整理发布记录。主图主体、关键链接、模型基本操作和待改项没有实际读回前，不进入下一步公开发布。

事实 / 案例 / 完成度边界

本文依据长期课程中的响应式页面、图片读回、GLB在线展示和移动端发布验收方法编写。当天视觉规划用原创陶瓷角色‘探窗豆’、无字手机样框、图片比例片和三维对象解释检查动作。配图是课程方向示意，不是真实学员、真实课堂、已上线网站、加载测速或设备测试案例。

3–5天通常只能围绕一个明确页面完成有限设备检查、局部修改和复核。课程不承诺覆盖所有手机、浏览器和网络，也不承诺模型在每台设备上都流畅、页面长期无故障、获得流量、订单或销售结果；制造文件仍需独立检查，网页模型能显示不等于可以打印。
