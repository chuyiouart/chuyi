具体问题

核心判断

以后还能改的作品页，通常有三个特点：作品数据与页面结构分开，重复区块使用同一套组件，样式能够在桌面和手机宽度下稳定调整。文件多、代码长或效果花哨，都不能代替这三点。

Codex适合根据现有项目结构新建组件、连接数据、补测试和解释报错，但人要先给它真实素材、技术边界和验收清单。每次只交一个能复核的改动，运行后查看实际页面和错误；如果工具没有看到真实结果，就不能把‘代码已经写完’当成页面已经可用。

步骤或标准

从一件作品和一条最短页面路径开始，先让结构能跑，再逐项增加内容。

  • 整理作品标题、简介、主图、细节图、展示模型、材料说明、作者与来源、完成阶段和行动入口；缺失内容明确留空，不让Codex补猜。
  • 读取现有项目的框架、目录、组件写法、样式方式和启动命令，再写清本次允许修改的文件与不能碰的范围。
  • 先画出最少区块和阅读顺序，把作品数据、可重复组件与页面样式分开；主图、画廊、模型和行动入口各有清楚位置。
  • 把任务拆成小步交给Codex，例如先建数据结构，再接一个组件，再处理手机布局；每一步都查看改动文件和实际运行结果。
  • 检查桌面与手机宽度、图片比例、链接、键盘操作、模型加载和浏览器报错；页面能打开不等于每项都通过。
  • 保留版本记录、未完成清单和回退点；发现组件互相挤压、数据重复或改动越补越乱时，退回最近可用版本后再缩小问题。

常见错误

页面后期难改，往往不是工具能力不够，而是输入、边界和验收被一次性混在一起。

  • 只说‘帮我做一个高级作品页’，却不给真实素材和现有项目结构。后果是Codex可能猜测内容、重建已有功能，或选用不适合当前仓库的做法。
  • 一次要求完成页面、动画、模型、后台和发布。后果是改动范围过大，出错后很难判断是哪一步造成的。
  • 把每篇作品内容直接写进页面组件。后果是新增作品必须复制代码，标题、图片和链接很容易改漏。
  • 只看桌面截图好看就通过。后果是手机布局、键盘操作、图片加载、模型错误和真实链接可能仍有问题。
  • 遇到错误就让Codex连续追加补丁。后果是重复样式和临时判断不断累积，最后没有人说得清当前版本为什么能运行。

与短期课程的关系

这项练习属于阶段5的独立站、三维展示与持续发布。做完后要能指出作品数据放在哪里，页面由哪些可复用组件组成，怎样启动和检查，以及一次修改失败后如何回到可用版本。发布验收看的是实际页面、链接和设备表现，不是生成了多少代码。

3天聚焦路线可以围绕一件作品完成资料整理、基础页面结构、一个展示组件和手机检查；4–5天可继续加入画廊、GLB在线展示、图片优化、更多作品数据和发布前复核。真实链接、模型加载、图文一致、版权和回退方式没有检查完，就不进入公开发布。
