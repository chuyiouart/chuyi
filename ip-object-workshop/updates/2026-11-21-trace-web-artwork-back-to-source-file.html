核心判断

网页文件只是派生结果。判断它对应哪一版，不能只比外观，还要一起核对作品特征、文件用途、保存位置、修改记录、导出时间和当前实物。网页图片能看出轮廓与颜色，网页模型能检查展示状态，但它们都不能单独证明源文件身份。

一条可靠关系至少要说清：网页正在用什么，派生文件从哪里导出，源文件是哪一版，当前实物或主模型是否仍与它一致。AI可以帮助列出候选、比较元数据和整理差异，最终仍要由人打开源文件、查看实际内容并确认导出链。

步骤或标准

从网页正在使用的一个对象开始倒查，比一次整理整个硬盘更容易得到可靠结果。

  • 记录网页当前使用的主图、细节图和展示模型，分别保存公开地址、页面位置、文件格式和可见特征；不先改名，也不覆盖现有文件。
  • 找到网页仓库或发布包中的实际派生文件，核对文件大小、修改记录和部署来源；同名文件要逐个打开，不凭目录名判断。
  • 沿导出记录、项目文件或工作说明回到候选源文件，区分原图、修图工程、展示模型、制造模型和网页压缩副本的用途。
  • 把候选源文件逐个打开，与网页和当前实物核对轮廓、部件、颜色、尺寸方向和缺失项；可见相同只能缩小范围，不能代替来源记录。
  • 确认源文件后，保存网页文件、派生文件、源文件和当前版本之间的对应说明；未确认的候选继续保留，不强行归并或删除。
  • 做一次小范围复查：从源文件重新导出到临时位置，核对结果是否与网页版本一致。确认无误后再安排更新，制造文件仍走独立检查。

常见错误

追溯失败通常不是文件太多，而是把相似外观、方便命名和真实来源混成了同一件事。

  • 看到文件名写着‘最终版’就认定它是网页源文件。后果是旧文件可能被当成当前版本，后续修改落在错误源头。
  • 只拿网页截图和候选模型比外观。后果是轮廓相似的不同版本会被混淆，隐藏部件、尺度和导出设置也无法确认。
  • 把GLB展示文件当成唯一主文件。后果是网页能转动的派生模型取代了可编辑源文件，制造检查和后续修模失去依据。
  • 为了整理干净直接删除未确认候选。后果是来源链一旦判断错误，就没有旧记录可供回查或恢复。
  • 让AI按文件名自动归类后直接采用。后果是模型可能把命名习惯当成事实，却没有打开文件、核对实物和导出关系。

与短期课程的关系

这项练习属于阶段5的独立站、三维展示与持续发布，也会回查阶段1到阶段4留下的源模型、实物、图片和说明。做完后要能指出网页正在使用哪些文件、它们从哪里导出、对应哪一版源文件，以及哪些候选仍未确认。

3天聚焦路线可以围绕一件作品完成一个页面对象的倒查、候选源文件核对和对应记录；4–5天可继续修正图片或模型、重做有限派生文件并复查手机与桌面页面。源文件身份、版权、当前实物和导出结果没有对上前，不进入下一步公开更新。
